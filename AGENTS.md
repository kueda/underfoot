Data prep repo for managing data packages for Underfoot, a mobile app for
viewing geologic and hydrologic maps. The [Progressive Web
App](https://github.com/kueda/underfoot-web) that displays this data lives in a
separate repo.

Each pack is specified as a .json file in packs/, including basic metadata and
lists of `rocks` sources for geology and `water` sources for hydrology. Each
source identifier references a python module in sources that will download
the source, process it, and insert it into a local PostGIS database. Most
geologic source modules include a citation.json file in CSL-JSON, and may
include a units.csv file that lists geologic unit descriptions that the
source did not include in a machine-readable format and needed to be derived
from a PDF pamphlet or a PDF or image map that came with the source.

## Development environment

The canonical environment is the Vagrant VM defined in `Vagrantfile` (Ubuntu
24.04, PostGIS 16, Python 3.12). Provisioning runs `.github/dependencies.sh`,
which installs the system packages (GDAL, mdbtools, PostGIS, etc.) and sets up
Postgres roles. After `vagrant up` and `vagrant ssh`, work from `/vagrant`:

```bash
./setup                    # first run only: builds bin/ tools, creates venv/
source venv/bin/activate   # required before every session
```

`./setup` compiles `bin/e00compr` and `bin/imposm3`, creates `venv/`, and
installs `requirements.txt`. `numpy` is pinned `<2.0` for GDAL and Fiona
compatibility.

`venv/` is created inside the VM, so its scripts are not runnable from the
macOS host. `venv-vagrant/` is an older Python 3.8 environment and can be
ignored.

Some source modules parse PDF pamphlets for unit descriptions and need
`pdftotext` (poppler). Install it if a source build asks for it.

## Building packs

Run everything from the repo root with the venv active:

```bash
python packs.py list                        # list available pack IDs
python packs.py us-ca-oakland               # build a full pack into build/
python packs.py us-ca-oakland --only rocks water
python packs.py us-ca-oakland --clean-rocks  # bust the rocks cache first
```

`packs.py` orchestrates the per-layer builders: `rocks.py` (geology),
`water.py` (hydrology), `elevation.py` (contours), and `osm.py` (ways and
context). Each builder runs the relevant source modules, loads their output
into the `underfoot` PostGIS database, and writes PMTiles to `build/`. Cached
source output lives in `sources/work-<name>/` and is reused across builds
unless a `--clean` or `--clean-<layer>` flag is passed.

## Working on a single source

```bash
python sources/<name>.py
```

This runs just that source module and writes standardized files to
`sources/work-<name>/` (for rocks, `units.geojson`) without touching the
database. Use it to check a new or changed source before adding it to a pack.
The expected output formats for rocks and water sources are documented in
`README.md`; helper functions are in the `sources/util/` module.

For adding a new geologic source, use the `underfoot-add-source` skill. For
creating a new pack, use the `underfoot-create-pack` skill; packs are always
generated by `create_pack.py` and never hand-edited.

## Tests

```bash
pytest
```

Run from the repo root. Coverage is limited; tests live in `tests/sources/`.
CI (`.github/workflows/run-tests.yml`) runs them on Python 3.8 while the VM has
3.12, so a test can pass locally and still fail in CI on version differences.
